# German Business Kit

A bundle of seven skills supports the lifecycle of a natural-person entrepreneur
in Germany. Read the [shared context and execution contract](references/shared-context.md).
One profile covers the person's activities, decisions and evidence; selecting a
skill never creates another profile or changes tax facts. Start with the user's
requested result; no GUI, workspace or accounting choice is required for a simple
question. English/Russian are supported; keep official German form labels.

## Select the task owner

| Requested result | Skill |
| --- | --- |
| Prepare to launch, classify or register an activity | [Business Start](../de-business-start/SKILL.md) |
| Customer proposal, invoice, payment follow-up or ordinary correspondence | [Business Operations](../de-business-operations/SKILL.md) |
| Review receipts, reconcile payments, post or prepare a period in the chosen system | [Business Accounting](../de-business-accounting/SKILL.md) |
| Tax question, sourced estimate, return or Finanzamt reply | [Business Tax](../de-business-tax/SKILL.md) |
| Choose banking/insurance/software or verify service access | [Business Services](../de-business-services/SKILL.md) |
| Change an activity, prepare hiring/migration, pause or close | [Business Changes](../de-business-changes/SKILL.md) |

Use the clear intent without forcing a menu. A specific skill can be used directly;
this router is not a prerequisite or a separate agent. For a mixed task, choose
one primary outcome, load only the relevant related instructions and retain
unresolved questions across the handoff. Do not ask for facts already confirmed. Apply the shared prerequisite and
remembered-fact process to every task: clarify material ambiguity, reuse relevant
saved context, ask targeted follow-ups and preserve confirmed information for
continuation.

## Start and continue

Use [guided onboarding](references/onboarding.md) for requested setup or usage help.
For “how do I use this?”, explain invocation and offer a few relevant copyable
requests with expected results; use the existing installation guide for setup.
For existing records use [existing-data intake](references/existing-data.md).
For continuation read only the relevant tasks, questions and evidence in the
chosen workspace; report completed work, open dependencies and the next action
across all activities, not just the accounting month.

The [lifecycle map](references/lifecycle.md) lists resource ownership. For help,
use the [Russian](guides/user-guide.ru.md#первая-задача) or [English](guides/user-guide.en.md#first-task) user guide.
Preserve originals and work history; use [recovery](references/recovery.md) for
backup/restore and validated shared writers for mutations. No second task register.

## Capability boundary

These skills provide guidance, readable preparation and supported local operations.
The limited cash journal, filing evidence, recovery and GUI are tools for those
journeys. Existing accounting software remains authoritative when selected.
There is no complete statutory ledger, embedded tax calculator, production
provider connector or ELSTER transport. Use actual host capabilities and current
sources; distinguish prepared documents, authorized actions and observed outcomes.
Self-managed reporting remains a supported goal; professional help is optional
for specific needs, never a compulsory endpoint replacing unfinished work.
