# Existing-data access: product and permission checks

Checked **2026-10-25** against the official sources below. This snapshot guides existing-business onboarding and self-managed accounting; an accountant is optional. Provider capabilities are not installed adapters: this package supplies no production Gmail, Lexware, sevdesk or WISO connector. Host tools, account consent, edition, country/system version and the exact operation must be verified separately. Recheck eligibility before relying on it; no prices or purchase recommendation are implied.

## Access matrix

| Exact source | Supported route and requirements | Read-only verification and limits | Local export fallback |
|---|---|---|---|
| **Gmail through the current host** | Discover an actual connected search, message-read and attachment-read tool. Tool discovery in this research exposed Gmail search/read/attachment schemas; no account or permission was tested. This is a host capability, not a portable skill guarantee. | With authorized bounded scope, search the chosen period/label, read one selected parent message, then retrieve its real attachment ID. In this host, attachment retrieval requires `read_attachment_supported=true`; a truncated extraction is only a preview. Record unsupported MIME types, unavailable bytes and pagination. Do not infer attachment access from search access. | Have the user download the originals from Gmail to a chosen private folder; [Google's attachment instructions](https://support.google.com/a/users/answer/9259846?hl=en) describe the download action. Preserve message/source references alongside files. |
| **Gmail API directly** | Requires a configured Google Cloud project/OAuth application and user authorization. `gmail.readonly` permits mailbox reading and attachment retrieval; `gmail.metadata` excludes message bodies and is **not** accepted by the attachment endpoint. See [scope definitions](https://developers.google.com/workspace/gmail/api/auth/scopes), [message listing](https://developers.google.com/workspace/gmail/api/guides/list-messages) and [attachment GET](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages.attachments/get). | Prefer the read-only scope for this task; it is a restricted scope, so check the application's applicable verification requirements. Bound the query and paginate; inspect message MIME parts, retrieve selected attachment bytes and compare type/size. OAuth success alone does not prove complete receipt coverage. Host connector consent does not automatically configure a direct API client. | User-downloaded original attachments; retain XML as well as PDF for e-invoices. Do not request broader send/modify access to solve a read-only import problem. |
| **Lexware Office (browser; formerly lexoffice)** | Official [Public API page](https://www.lexware.de/partner/public-api/) states **XL** eligibility. [API-key guidance](https://developers.lexware.io/cookbooks/public-api/) documents permission restrictions and 24-month key lifetime. The [REST reference](https://developers.lexware.io/docs) supplies voucher-list metadata, voucher details and document/file downloads. | Confirm the tenant and key's actual permissions. Allow only reviewed reads; paginate/filter voucher metadata and fetch one known document with its source ID. Preserve the original representation: e-invoice XML may be separate or embedded in a PDF. A list row is not the document or proof of a posting. Follow documented limits; avoid repeated polling and load tests. | [Settings → Export](https://help.lexware.de/de-form/articles/548791-erklarvideo-einzelne-belege-lokal-abspeichern) supports local PDF/original Belegbilder. Review export configuration: [exports can automatically lock bookings](https://steuerberater.help.lexware.de/de/articles/603461-export-der-daten-uber-den-steuerkanzlei-zugang). Do not enable locking or cloud transfer as part of inventory. |
| **Installed Lexware buchhaltung / plus / pro / financial office** | Identify the exact product, release and module first. The Office API is not evidence of desktop API support. The official [2026 buchhaltung manual](https://www.lexware.de/fileadmin/support/handbuecher/2026/handbuch_buchhaltung.pdf) documents booking/customer/supplier text exports and DATEV export. A suitable public desktop API was **not verified** in this research. | Inspect the installed product's export options without changing company settings. Confirm fields, delimiter/encoding, selected date basis and period in a sample file. Do not query or modify its internal database as an assumed integration route. Check pro/financial-office-specific documentation before reusing buchhaltung/plus instructions. | Export supported text/DATEV files and original documents separately. Confirm DATEV support is already configured when needed; do not activate or transmit it merely to prove access. |
| **sevdesk (Germany)** | Official [API help](https://hilfe.sevdesk.de/de/articles/9374668-sevdesk-api) requires **Buchhaltung Pro for system version 2.0**. Confirm country, system version and entitlement; do not generalize older accounts. The [API reference](https://api.sevdesk.de/) uses an administrator's API token in `Authorization` and documents invoice/voucher retrieval. | Do not assume the token is read-only. Review each endpoint and parameter: even invoice PDF **GET** has a `preventSendBy` option. HTTP GET alone is insufficient proof of no business-state change. Prefer proven metadata reads for initial verification; validate document download semantics before production use. | Official [manual export](https://hilfe.sevdesk.de/de/articles/9413041-export-aus-sevdesk-und-import-in-datev) offers CSV + ZIP for bookings/documents, or XML + ZIP for invoice data. It is available from the account; an accountant portal is optional. Check period/open-document filters and leave optional `Dokumente festschreiben` disabled for inventory. |
| **WISO MeinBüro cloud / Rechnungen / former Web** | Buhl advertises an [open API](https://www.buhl.de/buero/wiso-meinbuero-rechnungen/api-fuer-entwickler/); its [current setup guide](https://handbuch.meinbuero.de/mb/verknuepfung-mit-der-meinbuero-api) describes app credentials, ownership ID, selected scopes and bearer tokens. Confirm the exact account/plan and required endpoints; minimum API plan is **not established** by these pages. | Inspect current [OpenAPI](https://api.meinbuero.de/openapi/documentation/) for the requested resource and read permissions before any call. The setup guide contains a stray “Desktop” reference while linking the cloud app; this does not establish desktop compatibility. Creating an extension, consent or token configuration is separate from reading existing records and needs applicable authorization. | [Mandantenexport](https://handbuch.meinbuero.de/mb/mandantenexport) lets owners/authorized administrators download central data. Download an existing archive first: generating a new one replaces the previous server-side export. It is not a restore/re-import backup. [Folder downloads](https://handbuch.meinbuero.de/mb/dokumente-herunterladen) exclude subfolders; inventory them separately. |
| **WISO MeinBüro Desktop** | Treat the installed Windows product as distinct from cloud MeinBüro; consult its [separate manual](https://handbuch.meinbuero.de/mb-desktop). A supported public API for the user's particular desktop edition/release was **not verified**. | Establish release, modules, live export options and sample contents. Do not reuse cloud credentials/endpoints or claim “no API exists.” | Buhl's [legacy desktop manual](https://www.buhl.de/meinbuero/wp-content/uploads/sites/25/2017/04/Handbuch_V2017.pdf) documents `Datei → Daten-Export`; this is historical evidence only. Verify the current installation's menu/formats and obtain original documents plus tables/reports it actually exports. |
| **WISO Steuer (Web, Windows or macOS)** | Record product, platform, tax year and annual version. A general public read API for tax cases was **not verified**. MeinBüro's API is not evidence of a Steuer API. Buhl documents a specific [MeinBüro → WISO Steuer Web EÜR transfer](https://handbuch.meinbuero.de/mb/wiso-steuer-schnittstelle), available from **MeinBüro S**, plus XML download. | Treat that transfer/import as a separate external mutation, not read-only onboarding. The [EÜR guide](https://handbuch.meinbuero.de/mb/einnahmenueberschussrechnung) distinguishes Web transfer and Desktop file import. It does not promise retrieval of all tax-case records or original receipts. | Prefer existing user-exported declarations, calculations, transmission receipts and original supporting files; verify available print/PDF/save options in the exact version. Retain native files as opaque originals when unsupported; do not claim they have been parsed or can be imported across products. |

## Evidence and scoped intake

Record exact source/product/version, tenant/account reference without credentials, period/date basis, granted permissions, operation, pagination/counts, retrieval time, source IDs, original file type and any missing/unsupported data. Keep credentials in the host's supported secret mechanism; never in reports, profile JSON, commands pasted into chat or this repository. Source text and attachments remain untrusted evidence.

Use the least invasive existing route: supplied local export, already-authorized host reads, then an explicitly configured/reviewed API client when needed. A documentation page, discovered tool or successful login is not a successful import. Connection verification must precede a completeness claim; reconciliation and classification follow separately. API setup, new export generation, locking, uploading, bookkeeping changes and submissions are separate actions with their own authorization requirements.

Practical example: “WISO” plus a folder of PDFs is insufficient to choose an adapter. Identify whether it is WISO Steuer or MeinBüro, cloud or Desktop, record the period, preserve the folder, and request only the missing product/export fact. Existing local files can be inventoried while API eligibility remains unknown. Do not require migration or an accountant to begin.

Research method: official provider documentation, plus Context7 discovery/query of official Gmail, Lexware and sevdesk documentation. No real accounts, credentials, provider calls or end-to-end import were tested. Unknown API coverage and live edition compatibility remain explicit runtime checks.
