# Readable documents and delivery: source boundaries

Checked **2026-10-26**. Shared agent reference for preparing readable reports, letters and supporting documents. The ELSTER findings describe the public pages inspected on this date, not rules for every recipient, form or tax year. This note does not determine filing obligations or authorize a submission.

## A readable PDF and an official return are separate deliverables

[ELSTER's FAQ](https://www.elster.de/eportal/helpGlobal?themaGlobal=help_elster_eop), under downloadable/printable declaration forms, says those PDF forms cannot be transmitted with ELSTER. [ELSTER's legal guidance](https://www.elster.de/elsterweb/infoseite/rechtliches) separately requires the officially designated interfaces for the relevant period when transmitting prescribed datasets.

**Product consequence:** generate a readable report or letter for review, printing or an allowed attachment route; prepare a structured official return through the actual supported form/software route. A PDF export, a completed worksheet and an attachment upload do not prove that a prescribed return was filed. **Example:** a German report explaining recorded receipts and expenses may accompany a permitted request; it does not become an electronically submitted Anlage EÜR merely by being named `EUER.pdf`. See [submission integration sources](submission-integration-sources.md) for the separate transport boundary.

## Select the actual message or evidence route

- [ELSTER's Belegnachreichung landing page](https://www.elster.de/eportal/formulare-leistungen/alleformulare/belegnachreichung) identifies the dedicated evidence route. The official [Rheinland-Pfalz tax administration notice of 18 March 2026](https://lfst.rlp.de/nachrichten-1/nachichtendetailseite/digitalisierung-im-finanzamt) directs requested supporting evidence to **Belegnachreichung zur Steuererklärung** and advises submitting evidence on request or when the declaration specifically asks for it. **Consequence:** inspect the request and relevant declaration instructions before preparing an attachment bundle; do not routinely send every archived receipt.
- [Sonstige Nachricht an das Finanzamt](https://www.elster.de/eportal/formulare-leistungen/alleformulare/eingsonstnachr) expressly says to use a suitable dedicated form instead when available, including evidence submission, objections, deadline extensions and advance-payment adjustments. It also lists uses for informal applications. **Consequence:** do not route every polished German letter through Sonstige Nachricht. **Example:** a requested supporting-document bundle uses the evidence route rather than a generic message solely because a cover letter exists.

## Attachment limits are form-specific and must be refreshed

The current public help for [Belegnachreichung](https://www.elster.de/eportal/helpGlobal?themaGlobal=help_belegnachreichung) and, independently, [Sonstige Nachricht](https://www.elster.de/eportal/helpGlobal?themaGlobal=help_eing_sonstnachr) each states:

| Limit | Public help on the checked date |
| --- | --- |
| PDF pages per attachment | 200 |
| Size per attachment | 10 MB |
| Combined attachment size | 36.91 MB (displayed as `36,91 MB`) |
| Number of attachments | 20 |

Both warn that evidence exceeding the page limit can be deleted without further feedback. **Consequence:** count actual exported pages and file sizes, keep headroom, and split logically with a German attachment index when necessary. Do not reuse these limits for another contact form: the [Rheinland-Pfalz notice](https://lfst.rlp.de/nachrichten-1/nachichtendetailseite/digitalisierung-im-finanzamt) describes a separate account-free contact route with up to five PDF attachments.

Before delivery inspect the **exact selected current form**, version, attachment control and recipient instructions for accepted formats, limits and any signature requirements. Public help establishes the PDF limits above; it does not establish every accepted extension or an exhaustive current format policy. An indexed official portal description mentioned PDF files and E-Rechnungen, but its alternate-host direct fetch failed and the main landing-page extract omitted that description. Do not infer accepted XML/hybrid profiles from that snippet. No authenticated form was opened and no upload or transmission was attempted. The inspected sources do not establish a universal PDF/A requirement; check any recipient-specific requirement separately.

## Native document export and its verification

[Microsoft's Edge printing guide](https://support.microsoft.com/en-us/edge/print-in-microsoft-edge) documents Windows `Ctrl+P`, A4 selection, margins, scale and print preview. [Microsoft's official known-issues page](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-known-issues) distinguishes Edge's **Save As PDF** from the Windows **Microsoft Print to PDF** printer; it records a version-154 printer failure and its fix in 154.0.4258.48. **Consequence:** a Windows browser print-to-PDF route is a practical local export option, but file creation and visual inspection must succeed on the actual host. Documentation is not a live desktop compatibility test.

Delivery design choices, rather than claims about legal requirements: retain an editable local source; provide the recipient-facing document in German and the user's explanation/review checklist in Russian when that mode is selected. Reopen the exported PDF and inspect every page for readable tables, dates, amounts, page breaks, missing characters and accidental browser headers. Keep unconfirmed facts visibly unresolved. A successful export establishes a local artifact, not recipient acceptance, official validation or transmission evidence.
