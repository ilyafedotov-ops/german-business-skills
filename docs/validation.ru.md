[English](validation.md) | [Русский](validation.ru.md)

Проверено **25.10.2026**. Используются синтетические временные данные, без реальных деловых документов и аккаунтов.

## Автоматические локальные проверки

Набор Python-тестов содержит **47 успешно пройденных тестов**: **10 для установщика** и **37 для рабочего пространства**. Восемь новых тестов проверяют сохранение языка/режима, совместимость, историю, неверные запросы и сохранность налоговых фактов.

```bash
python3 -B -m unittest discover -s tests -v
python3 tools/check_package.py
```

Skill также проходит доступную проверку имени и frontmatter из skill-creator. Проверка пакета контролирует обязательные файлы, локальные Markdown-ссылки, самостоятельность устанавливаемого skill, синтаксис JSON и одинаковый набор ролей шаблонов на английском и русском. Она не проверяет каждый внешний источник, качество перевода или юридическую точность.

Исходный синтетический сквозной запуск v0.1 создал рабочую папку, записал факт, импортировал оригинальные байты CSV, сверил примеры, проверил целостность и установил skill в каталоги обоих приложений для проекта. Результат: **3 совпавшие группы и 1 банковская операция без соответствия**, статус `needs_review`. Это проверка локальных файлов и установщика, без desktop-интерфейсов. Полный набор локальных тестов выше повторно выполнен для v0.2.

## Проверки поведения

Одна новая сессия агента использовала skill для синтетического случая добавления SaaS/Gewerbe при уже действующей Regelbesteuerung, имея только файлы и web search. Она сохранила общий контекст НДС предпринимателя, различила прогноз новой деятельности в форме и общие пороги, подготовила полезные поля, задала точные вопросы и не выдумала доступ к браузеру или факт подачи.

Эта исходная проверка выполнена для v0.1. Две дополнительные новые сессии агента использовали инструкции v0.2 и только данные своих задач; критерии оценки и выводы разработчиков им не передавались. Полученные ответы и файлы просмотрены:

| Сценарий | Наблюдаемый результат |
|---|---|
| Налоговый консультант на русском: оборот 60 000 EUR, расходы 15 000 EUR, достаточно ли резерва 30%? | Ответ на русском; разделены условная арифметика бизнеса, НДС и налогооблагаемый доход; проверены официальные источники; рассчитан явно условный пример тарифа; нет гарантии универсального резерва или требования раскрыть все личные сведения; папка не создана, документы не поданы |
| Отчёт за октябрь на английском при сохранённых `ru` / `bookkeeping` | Сохранён английский отчёт; встроенная сверка нашла три совпавшие группы и один непривязанный платёж 12 EUR; валюты разделены, отсутствие документов и неполнота месяца явно обозначены; сохранён `needs_review`; повторное чтение подтвердило неизменность настроек |

Вторая проверка также сохранила оба исходных CSV, создала две идентичные по байтам индексированные копии и успешно проверила их целостность. Отчёт различал предоставленные нормализованные данные и оригинальные банковские выписки; проводки, налоговый подход или внешняя передача не выдумывались. Временные папки содержали только синтетические данные и удалены после просмотра.

Среда: сессии агента с локальной файловой системой/Python, а для налогового вопроса — публичный web search. Версия desktop-приложения не участвовала; конкретная сборка модели не фиксировалась. Это ограниченные проверки поведения, а не сравнительный тест моделей.

**18 запросов** в `evals/scenarios.json` образуют повторно используемый набор; не все они выполнены. Эти примеры не являются полной юридической проверкой или измерением надёжности модели.

## Интеграции, ещё не проверенные в работе

- Обнаружение skill и полные сценарии в реальных версиях Codex/Claude Code desktop на операционных системах пользователя.
- Реальные ELSTER, муниципальные порталы, аутентификация в браузере и отправка налоговых документов.
- Коннектор к Lexware/банку: в этом выпуске он не реализован.
- Договорные настройки и защита данных конкретных поставщиков для реального бизнеса.
- Соответствие полного процесса учёта, хранения и оказываемых услуг применимым требованиям.

Проверяйте значимые решения по актуальным первичным источникам для нужного периода. Прохождение Python-тестов не фиксирует правовые или продуктовые правила навсегда.

## Практические ограничения

Атомарная замена JSON защищает отдельный файл, но копии, индекс, история и события не объединены в одну транзакцию. Жёсткое прерывание может оставить обнаруживаемый файл вне индекса или отсутствие события после обновления индекса. Проверяйте состояние перед повтором. Блокировки координируют эти утилиты, а не произвольные внешние редакторы. Хеши не являются подписями и не создают защищённый от изменений архив. POSIX-права применяются по возможности; Windows ACL, шифрование и резервирование зависят от среды пользователя.

README задаёт порядок установки: сначала создать новую личную рабочую папку, затем устанавливать skill для проекта внутрь неё. Установка для пользователя возможна до инициализации.
