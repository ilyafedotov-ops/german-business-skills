## Выполняйте подходящие проверки

Из checkout, с существующим runtime разработчика:

```sh
python3 -B tools/check_package.py
python3 -B -m unittest discover -s tests -v
git diff --check
```

Дополнительные проверки выбираются по изменённой области в [AGENTS.md](../AGENTS.md#validation-and-delivery): native Windows, обзор, восстановление, GUI, печатные документы, испытания скиллов или упаковка. Для документации нужны проверки пакета/ссылок/якорей/паритета; перенос ресурсов требует также detached-package проверки. Собирайте в новую абсолютную папку вне checkout. Node/Playwright и Python разработчика не являются требованиями к пользователю.

Native Windows требует Windows PowerShell 5.1 на Windows; PowerShell на macOS/Linux не эквивалентен. Свежий сеанс испытания скилла должен фиксировать хост/версию, реальные инструменты и наблюдаемые результаты без раскрытия критериев модели. Успешный тест, загрузка CI, health endpoint или аккуратный файл не подтверждают внешнее действие.

### Разбор CI релиза и диагностика браузера — 2026-10-26

На head PR выпуска `dc05b32` Python и JavaScript CodeQL сформировали SARIF, но завершились ошибкой при загрузке без поясняющего сообщения; повтор только неудачных jobs без изменения исходников прошёл. Actions-скан прошёл локальную SARIF-политику с нулём находок, однако GitHub не успел обработать загрузку и не зарегистрировал анализ. Нейтральный общий check не считается полной приёмкой сканирования.

Windows Chromium также превысил ожидание при перезагрузке сохранённого документа (`tests/gui-browser.cjs:416`). Предыдущие запросы записи/восстановления успешны, но после reload браузер не отправил API-запрос, а атрибут busy отсутствовал. Имеющиеся логи не позволяли отличить сбой загрузки скрипта от синхронного исключения запуска. Это невыясненная исходная ошибка CI, а не подтверждение сбоя бухгалтерской записи или основание увеличить таймауты.

Диагностика только в тесте теперь выводит ограниченные результаты статических путей, готовность страницы/переводов, ошибки браузера и stderr сервера с заменой известного токена сессии, а также вымышленный снимок ошибки. Код приложения, assertions и таймауты не менялись. Независимое read-only ревью не нашло блокеров. Временный контролируемый probe блокировал `i18n.js`: ожидаемо завершился ошибкой и показал конкретный скрипт, отсутствие переводов и TypeError запуска. Это проверяет диагностический вывод, а не причину исходной ошибки Windows. Статус ответа означает получение заголовков, а не выполнение скрипта.

`npm run test:gui -- --browser=chromium` и `--browser=webkit` локально прошли: реальные записи/восстановление/stale-tab, 54 проверки локализованных экранов/ширин и шесть task-home на браузер. WebKit сообщил 17 существующих screenshot-only CSP-диагностик под узким фильтром снимков; Chromium — ни одной. Логи: `/private/tmp/gbk-090-gui-{chromium,webkit}.log`, `/private/tmp/gbk-090-missing-script.log`; исходный CI: `/private/tmp/gbk-090-{windows-browser,codeql-python,codeql-js,codeql-actions}.log`.
