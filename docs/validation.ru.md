## Нативный путь Windows без Python (25.10.2026)

Настройка Windows теперь предпочитает инструменты хоста и `scripts/windows.ps1`, рассчитанный на Windows PowerShell 5.1. Нативные операции: установка skill, создание/продолжение общей рабочей папки, ограниченный предпросмотр источника, приём оригиналов, одинаковые байты и проверка целостности. Профиль, индекс и блокировка общие с необязательным Python-движком; второго реестра или миграции нет. Расширенные проверяемые записи/предложения/сверка/XML/обзор/архив пока требуют прежний движок. Руководства раскрывают границу и запрещают выдавать ручные изменения JSON за проверяемые операции.

Полный набор сначала обнаружил отсутствие разрешения упаковки PowerShell; сборщик теперь разрешает ровно проверенный скрипт и требует его шаблон/справочник. Python-зависимость для пользователя не добавлена.

Исполняемая проверка: PowerShell **7.5.12**, изолированный контейнер **Debian 12** без сети, официальный образ Microsoft `mcr.microsoft.com/dotnet/sdk:9.0` (digest `sha256:d7cfd59385751fc87897a138ba173fb1bbc2bf946ea78aecc91a119993676997`). Самостоятельный учёт и отчётность остаются основным сценарием.

Конкретные записи реестров, поставщики, актуальные котировки, премии и покрытие пользователя не проверялись.

## Практические ограничения

Атомарная замена JSON защищает отдельный файл, но копии, индекс, история и события не объединены в одну транзакцию. Жёсткое прерывание может оставить обнаруживаемый файл вне индекса или отсутствие события после обновления индекса. Проверяйте состояние перед повтором. Блокировки координируют эти утилиты, а не произвольные внешние редакторы. Хеши не являются подписями и не создают защищённый от изменений архив. POSIX-права применяются по возможности; Windows ACL, шифрование и резервирование зависят от среды пользователя.

README задаёт порядок установки: сначала создать новую личную рабочую папку, затем устанавливать skill для проекта внутрь неё. Установка для пользователя возможна до инициализации.
