# Windows: начало работы без установки Python

[English](windows.md) | [Русский](windows.ru.md) | [Начало работы](quickstart.ru.md)

Используйте уже установленный Codex или Claude Code. **Python, Git, WSL и PowerShell 7 не нужны для нативного запуска и приёма документов на Windows.** Ассистент использует доступные инструменты приложения и Windows PowerShell 5.1. Самостоятельно вводить команды или редактировать JSON не требуется.

1. Откройте локальную сессию с папкой. Получите проверенный skill/плагин; ZIP исходников можно распаковать через «Извлечь всё» в Проводнике. Храните его отдельно от деловых документов. Ассистент может установить отдельный skill нативным установщиком, без менеджера пакетов.
2. Напишите: «У меня Windows без Python. Используй штатные инструменты Windows. Помоги организовать существующие документы в отдельной личной папке, покажи учебный приём файлов и продолжай без установки инструментов разработчика».
3. Ассистент проверит инструменты и разрешения, создаст либо продолжит рабочую папку. Перед импортом выбранных поддерживаемых файлов покажет состав исходной папки, сохранит оригиналы и проверит хеши.
4. Он объяснит открытые вопросы и сохранит понятный отчёт для продолжения. История деятельности и НДС останется в общей рабочей папке.

Исследования, налоговые объяснения, сравнение услуг и рабочие листы форм не требуют Python. Нативные команды сейчас покрывают установку, запуск/продолжение, предпросмотр папки, приём оригиналов, поиск одинаковых байтов и проверку целостности. Они не делают проводки и не подают отчётность.

Часть расширенной автоматизации пока использует необязательный Python-движок: проверяемые изменения записей, каталог/предложения, банковские сопоставления и сверка, разбор XML, создаваемые обзоры и архивы. Если среды нет, ассистент продолжает полезную подготовку и указывает конкретную невыполненную операцию. Он не должен автоматически устанавливать Python или выдавать ручные изменения записей за проверенные результаты. При необходимости можно использовать уже доступную согласованную среду; дополнительный инструмент или удалённая обработка требуют отдельной конкретной оценки.

Блокировку скрипта политикой Windows/организации нельзя обходить ради завершения настройки. Ассистент не отключает защиту. Локальные файловые операции также не означают локальную AI-модель: перед настоящими персональными данными нужно оценить реальный поток обработки.

[Справочник нативных команд](../skills/de-business-kit/references/native-windows.md) предназначен для ассистента. [Проверки](validation.ru.md) отделяют выполненные тесты от ожидающей приёмки Windows/desktop. Это предварительная возможность, а не заявление о переносе всей прежней автоматизации.
