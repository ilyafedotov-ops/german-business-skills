# Current project status and roadmap

[English](project-status.md) · [Русский](project-status.ru.md) · [Technical documentation](index.md)

Updated **2026-11-21**: onboarding, the workspace folder structure and the releases were checked against source that day; the other capability statements were reviewed on **2026-10-26** and **2026-10-27**. German Business Kit is a seven-skill system for a natural-person entrepreneur in Germany: preparation, formation, everyday work, accounting, reporting, changes and closure. Users can ask a question before creating a workspace or choosing accounting software. Self-managed accounting remains a supported goal; consultation and sharing with an accountant are optional.

## Primary user journey

Use Claude Code, the Claude app (Cowork) or Codex as the interface, and one private business folder for records, confirmed facts, open questions and continuation. After installation, a [welcome wizard](../skills/de-business-kit/references/welcome.md) in the chat runs a read-only setup check and guides a new user one step at a time through language, situation, business folder, data handling and a first task. There is no separate application: the former local GUI and the fictional browser prototype were removed in 0.14 because the assistant apps are the interface; prioritize observed assistant journeys. Installation and connection success still require actual observation.

All seven skills share task-specific prerequisite checks, targeted follow-ups, reuse of saved facts and persistence through existing writers, a [cost check before setup](../skills/de-business-kit/references/assisted-services.md#check-costs-before-setup) and a [screenshot privacy check](../skills/de-business-kit/references/privacy.md#check-screenshots-before-sharing). Tax and accounting work may use [bounded source-led calculations](../skills/de-business-kit/references/tax-estimates.md) from inspected rules, with executed arithmetic and separately evidenced checks. These are instruction-level safeguards over the host's tools, not a bundled tax engine, billing enforcement or automatic redactor; [validation](validation.md) records actual trials and limits.

Users need neither JSON editing nor development dependencies. Assistant tools and standalone scripts have different capability sets; see [architecture](architecture.md).

The published source also projects invoice payment allocations across periods, exposes discrepancies in the report and checks settlement-basis freshness before filing actions. Native PowerShell supports lock diagnosis/recovery, including exact raw evidence. An opt-in [evaluation runner](../evals/README.md) executes selected fresh-session cases on supported POSIX developer hosts; it does not certify behavior from a passing utility test. The repository root is a Claude plugin [marketplace](distribution.md#github-marketplace-for-claude) that installs the verified preview pinned by tag and commit; the README and installation guides lead with that three-step Cowork route. A Cowork desktop installation has not been observed. Desktop signing and provider journeys outside the accepted Lexware browser scope remain open.

The [FAQ evaluation map](../evals/faq-coverage.json), reviewed on **2026-10-27**, links 60 external question numbers to task owners and cases. Do not replace the chosen accounting system just to complete the roadmap.

## Accounting acceptance

The first developed monthly route is **explicitly chosen local cash records plus manual ELSTER**, not a default for everyone. Follow the [monthly](../skills/de-business-kit/references/monthly-workflow.md) and [annual](../skills/de-business-kit/references/annual-workflow.md) workflows. Full backup/restore and the real overview are implemented; they do not establish complete statutory accounting.

| Area | Evidence still needed before an end-to-end claim |
| --- | --- |
| Documents and ledger | Complete source/account/period coverage; reviewed treatment, assets/noncash adjustments, closing rules and verified reports in the authoritative system; format/host and technical e-invoice validation where applicable |
| Tax estimates and returns | Applicable official rules and form/year support; evidenced inputs and actual selected official/provider tool output; reconcile differences. Bounded case calculations need applicable sourced methods, sufficient inputs, executed output and independent check evidence; no reusable package tax constants or invented amounts |
| Submission | Supported official route/access; user-controlled authentication; exact payload preview and matching authorization; technical validation, duplicate prevention, timeout/retry investigation, actual receipt and correction workflow. A new adapter needs a supported official test environment and independent credential/authorization review |
| Authority follow-up | Observed response linked to the exact filing version; separately sourced deadline checks and objections/corrections. A transmission receipt is not substantive acceptance |

The evidence chain remains **source → proposal → review → actual accounting entry → return draft → submission authorization → observed submission → authority response**. A verified manual step can complete part of a supported assistance journey; it is not evidence of automated integration. See [validation](validation.md) for what has actually been tested.
