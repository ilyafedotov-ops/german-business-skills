# Папки рабочего пространства и язык

[English](folder-structure.md) | [Русский](folder-structure.ru.md) | [Deutsch](folder-structure.de.md)

Новые пространства, созданные через `start` или команду `init`, получают настоящие названия папок на русском, немецком или английском. Язык выбирается при создании. Существующие пространства сохраняют свои пути. Основной сценарий — самостоятельный учёт; выгрузки необязательны.

## Пять повседневных разделов

| Папка | Назначение |
| --- | --- |
| `01 Входящие` | Смешанные файлы, которые ещё нужно разобрать |
| `02 Документы` | Сохранённые оригиналы и результаты обработки |
| `03 Учёт` | Выписки, бухгалтерские записи и отчёты |
| `04 Налоги` | Подготовка деклараций и подтверждения отправки |
| `05 Бизнес` | Регистрация и деловая переписка |

В корне создаётся руководство `НАЧНИТЕ-ЗДЕСЬ.md`. Положите смешанные файлы во входящие; помощник поможет разобрать их без предварительного выбора налоговой категории. Само копирование во входящие ещё не означает импорт или проверку.

Месяцы появляются по мере работы, например `02 Документы/2026/10/Оригиналы/`. Импорт сохраняет исходные байты и записывает имя источника; архивная копия получает прежнее имя на основе хеша. Месяц хранения не определяет налоговый период. Несколько задач могут ссылаться на один оригинал без лишних копий.

Профиль, индексы и история находятся в `.business-kit`, а язык папок — в `.workspace-layout.json`. Обе части обязательно входят в резервную копию. Скрытие технических файлов не защищает доступ. Не редактируйте их и не переименовывайте папки вручную.

## Язык и совместимость

Переключение языка помощника или отчёта не переименовывает архив. Внутренние ссылки остаются стабильными и автоматически преобразуются в реальные пути. Перед работой обычными файловыми инструментами помощник получает карту через `workspace.py folders --root <папка>` или `windows.ps1 -Action folders -Root <папка>`. Английские пути в технической документации обозначают внутренние ссылки.

Новые пространства используют перевод по умолчанию; `--layout legacy` / `-Layout legacy` явно выбирает старую структуру. Низкоуровневая функция Python `init_workspace` сохраняет старый вариант по умолчанию для совместимости; `start_workspace` создаёт переведённые папки. Старые пространства продолжают работать без переноса. Автоматической миграции нет: для неё нужны предварительный просмотр, проверенная резервная копия, контроль конфликтов, ссылок и хешей оригиналов.

Встроенные команды Windows для создания, просмотра источника, импорта и проверки используют ту же карту, что и дополнительные функции Python, отчёты и архивы. Это не переносит все расширенные функции Python в Windows. Немецкие папки и стартовое руководство готовы; полный перевод прототипа и всех отчётов ещё не выполнен. Проверка PowerShell в Linux не заменяет проверку Windows PowerShell 5.1. См. [результаты проверок](validation.ru.md) и [таблицу трёх языков](folder-structure.md).
