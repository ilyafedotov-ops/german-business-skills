# Текущее состояние проекта и план

[English](project-status.md) · [Русский](project-status.ru.md) · [Техническая документация](index.ru.md)

Обновлено **21.11.2026**: в этот день с исходниками сверены первое знакомство, структура рабочей папки и выпуски; остальные утверждения о возможностях сверены **26.10.2026** и **27.10.2026**. German Business Kit — система из семи скиллов для предпринимателя — физического лица в Германии: подготовка, открытие, ежедневная работа, учёт, отчётность, изменения и закрытие. Задать вопрос можно до создания рабочего пространства или выбора бухгалтерской программы. Самостоятельный учёт остаётся поддерживаемой целью; консультация и передача материалов бухгалтеру необязательны.

## Основной путь пользователя

Интерфейс — Claude Code, приложение Claude (Cowork) или Codex, плюс одна личная папка бизнеса для записей, подтверждённых фактов, открытых вопросов и продолжения. После установки [приветственный мастер](../skills/de-business-kit/references/welcome.md) в чате выполняет проверку настройки только для чтения и по шагам ведёт нового пользователя: язык, ситуация, папка бизнеса, обращение с данными и первая задача. Отдельный GUI — необязательный адаптер для существующих локальных операций, а не условие для начала работы, ежедневных задач или самостоятельной отчётности; сначала развивайте наблюдаемые пути с ассистентом, а не GUI. Успех установки и подключений по-прежнему требует фактического наблюдения.

Все семь скиллов используют проверку условий конкретной задачи, точечные уточнения, повторное использование сохранённых фактов и запись через существующие механизмы, [проверку стоимости до настройки](../skills/de-business-kit/references/assisted-services.md#check-costs-before-setup) и [проверку приватности скриншотов](../skills/de-business-kit/references/privacy.md#check-screenshots-before-sharing). Для налогов и учёта допустимы [ограниченные расчёты на основе источников](../skills/de-business-kit/references/tax-estimates.md) по изученным правилам, с выполненной арифметикой и отдельно подтверждёнными проверками. Это правила инструкций поверх инструментов хоста, а не встроенный налоговый движок, блокировка оплаты или автоматическое скрытие данных; фактические испытания и ограничения — в [сводке проверок](validation.ru.md).

[архитектуру](architecture.ru.md) и [GUI](gui.ru.md).

Опубликованные исходники также показывают распределение платежей по счетам между периодами, расхождения в GUI/отчёте и проверяют свежесть основы сверки перед действиями с подачей. Native PowerShell диагностирует и снимает оставшиеся блокировки с сохранением точных исходных байтов. Необязательный [оценочный runner](../evals/README.ru.md) выполняет выбранные сценарии в новых сессиях на поддерживаемых POSIX-хостах разработчика; успешный тест утилиты не доказывает качество поведения. Корень репозитория — [маркетплейс](distribution.ru.md#маркетплейс-на-github-для-claude) плагинов Claude, который устанавливает проверенный preview, закреплённый по тегу и коммиту; README и руководства по установке начинаются с этого пути через Cowork в три шага. Установка в настольном Cowork ещё не наблюдалась. Подписание приложений и сценарии сервисов вне принятого браузерного объёма Lexware остаются открытыми.

## Приёмка учёта и отчётности

Первый разработанный месячный путь — **явно выбранный локальный денежный журнал и ручной ELSTER**, а не общий вариант по умолчанию. Используйте [месячный](../skills/de-business-kit/references/monthly-workflow.md) и [годовой](../skills/de-business-kit/references/annual-workflow.md) процессы. Полное восстановление и реальный обзор реализованы, но не доказывают полноценный регламентированный учёт.

| Область | Что ещё требуется для заявления о полном процессе |
| --- | --- |
| Документы и регистр | Полнота источников/счетов/периода; проверенное отражение, основные средства/неденежные корректировки, закрытие и отчёты основной системы; приёмка форматов/хостов и техническая валидация электронных счетов по необходимости |
| Оценки налогов и декларации | Применимые официальные правила и поддержка формы/года; подтверждённые входные данные и фактический результат выбранного официального/провайдерского инструмента; разбор расхождений. Ограниченные расчёты требуют применимого метода по источникам, достаточных данных, фактического выполнения и независимой проверки; без налоговых констант пакета и выдуманных сумм |
| Подача | Поддерживаемый официальный путь/доступ; аутентификация пользователя; просмотр точной нагрузки и соответствующее разрешение; техническая проверка, защита от дублей, разбор таймаутов/повторов, фактическая квитанция и исправление. Новому адаптеру нужны поддерживаемая официальная тестовая среда и независимая проверка секретов/разрешений |
| Ответ ведомства | Наблюдаемый ответ, связанный с точной версией подачи; отдельно проверенные сроки и процесс возражений/исправлений. Квитанция передачи не означает согласия по существу |

Цепочка остаётся прежней: **источник → предложение → проверка → фактическая запись → черновик декларации → разрешение подачи → наблюдаемая подача → ответ ведомства**. Проверенный ручной шаг может завершать часть сопровождаемого процесса, но не доказывает автоматическую интеграцию. Фактически выполненные проверки — в [сводке](validation.ru.md).
