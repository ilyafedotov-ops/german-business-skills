# Текущее состояние проекта

[English](project-status.md) | [Русский](project-status.ru.md) | [Документация](index.ru.md)

Сверено с локальным кодом **26.10.2026**, кандидат исходников **0.7.0-preview.1** (ещё не опубликован).
Страница описывает реализованные возможности. Локальные результаты кандидата GUI описаны в [руководстве GUI](gui.ru.md) и журнале проверок; предыдущая [опубликованная предварительная версия](https://github.com/ilyafedotov-ops/german-business-skills/releases/tag/v0.6.0-preview.4)
прошла [процесс выпуска](https://github.com/ilyafedotov-ops/german-business-skills/actions/runs/40288755911);
тот запуск проверяет прежнюю базу, а не новый GUI. Ни один результат не подтверждает успешную установку в приложении или сертифицированный процесс учёта. Конкретные
запуски и ограничения находятся в [журнале проверок](validation.ru.md);
прежние записи в нём являются историческими.

Основной сценарий — **самостоятельный учёт и налоговая отчётность**. Первый
развиваемый сквозной маршрут — **локальный денежный журнал и ручная подача через
ELSTER**. Это не выбор локального учёта за каждого пользователя: если выбрана
существующая программа, её записи остаются основными. Консультация специалиста
и передача архива необязательны.

| Возможность | Реализовано | Граница |
| --- | --- | --- |
| Приём и продолжение | Общий профиль, сохранение оригиналов, папки EN/RU/DE, запуск/продолжение и проверка целостности | Язык папок не меняет налоговые факты; скрытой миграции нет |
| Нативный Windows | PowerShell 5.1: установка, приём, проверка, реальный обзор и полное копирование/восстановление без установки Python | Проверки штатного Windows PowerShell 5.1 прошли в указанном запуске выпуска; установка в desktop-приложении и приёмка с нетехническими пользователями проверяются отдельно |
| Документы | Каталог, предложения, источники, банковское сопоставление, сверка и ограниченный разбор XML через необязательный Python-движок | Нет полного конвейера OCR, извлечения XML из PDF и технической проверки электронных счетов |

| Доказательства подачи | Версии, предварительные проверки, одобрение/разрешение, неопределённые попытки, фактические квитанции и ответы ведомства | Локальный реестр ничего не отправляет; расчётный инструмент и ручной ELSTER требуют реального доступа и наблюдаемого результата |
| Реальный обзор | HTML/Markdown/JSON EN/RU из основных записей: вопросы, выбор учёта, подачи и следующий шаг | Снимок только для чтения; нативный вариант проверяет сохранённые доказательства, но не выполняет полную проверку подачи |
| Восстановление | Полная копия папки с манифестом/хешами, проверенное восстановление в новую папку, общий формат Python/PowerShell | Нет перезаписи, автоматического ремонта, шифрования, внешнего хранения или службы копирования по расписанию |
| Настоящий локальный GUI | Интерфейс EN/RU/DE с проверяемым импортом/каталогом, денежными записями/исправлениями, действиями подачи, черновиками и восстановлением | Новый кандидат отдельного приложения со встроенной средой; CI платформ и пользовательская приёмка — отдельные этапы. Отправки в ELSTER нет |
| Интерактивная демонстрация | Отдельный английский прототип с вымышленными записями и хранением в браузере | Только учебные данные, не настоящий GUI |
| Внешние источники и напоминания | Инструкции доступа через плагины/API/браузер/компьютер, карты источников и даты с основаниями | Нет встроенных производственных коннекторов и автоматического планировщика напоминаний |

Пользователь не обязан знать команды или редактировать JSON. Ассистент выбирает
действительно доступный способ и называет конкретную заблокированную операцию.
Node/Playwright и Python для тестов нужны разработчикам, а не для начала работы.
Наличие Python на macOS также не предполагается.

## Следующие критерии готовности

1. Выполнить проверки готовых GUI-пакетов и первого запуска на Windows и обеих
   архитектурах Mac. Встроенный движок не требует установки Python пользователем;
   самостоятельный PowerShell сохраняет более узкий набор операций.
2. Проверить характерный реальный месяц и поддерживаемые форму/год через выбранный
   расчётный инструмент и ручной ELSTER; сохранить реальные доказательства приватно.
3. Проверить первый запуск подключённого GUI, восстановление после ошибок и
   продолжение сессий с нетехническими пользователями Windows/macOS.
4. Добавлять напоминания через определённый разрешённый планировщик с проверкой
   доставки; сохранённая дата ещё не является напоминанием.

## Ответственность документации

Код, схемы команд и тесты определяют, что реализовано. Эта страница описывает
текущий объём; архитектура и онтология объясняют устройство; переносимые инструкции
направляют установленного ассистента; пользовательские руководства объясняют
задачи. Датированные исследования фиксируют проверку источников, журнал валидации —
реальные запуски. Обновление описания кода не обновляет правовое исследование и не
подтверждает GitHub CI. Сохраняйте это разделение; см. [AGENTS.md](../AGENTS.md)
и [правила участия](../CONTRIBUTING.ru.md).

Выпуски: единая версия, воспроизводимые пакеты и проверка происхождения описаны в [Версии, подписи и проверка выпусков](releases.ru.md).
