# Текущее состояние проекта

[English](project-status.md) | [Русский](project-status.ru.md) | [Документация](index.ru.md)

Сверено с исходниками **26.10.2026**, версия **0.7.0-preview.1**.
Страница описывает реализованные возможности. Загрузка доступна после успешных
проверок платформ, публикации и проверки соответствующих файлов на
[странице версии](https://github.com/ilyafedotov-ops/german-business-skills/releases/tag/v0.7.0-preview.1).
Объём поставки описан в [руководстве GUI](gui.ru.md), фактические запуски и их
ограничения — в [журнале проверок](validation.ru.md). Исторические запуски выпусков
не подтверждают приёмку нового GUI; локальные проверки и GitHub CI не доказывают
удобство для нетехнических пользователей или сертифицированный процесс учёта.

Назначение продукта — **система скиллов для всего жизненного цикла предпринимателя**. [Полный план исправления](lifecycle.ru.md) задаёт целевую структуру, покрытие, последовательность P0–P7 и критерии приёмки. Инструкции уже охватывают открытие, формы, вопросы, сервисы, документы и отчётность; добавлены инструкции ежедневной работы, годовой подготовки, изменений и закрытия, с отдельной приёмкой реального исполнения. Таблица ниже описывает преимущественно техническую основу, а не весь охват продукта. Самостоятельный учёт и подача остаются важным направлением: локальный журнал с ручным ELSTER — один маршрут, существующая программа остаётся основной при её выборе. Консультация и экспорт необязательны.

| Интерактивная демонстрация | Отдельный английский прототип с вымышленными записями и хранением в браузере | Только учебные данные, не настоящий GUI |

Пользователь не обязан знать команды или редактировать JSON. Ассистент выбирает
действительно доступный способ и называет конкретную заблокированную операцию.
Node/Playwright и Python для тестов нужны разработчикам, а не для начала работы.
Наличие Python на macOS также не предполагается.

## Следующая работа по продукту

После разделения комплекта и реализации инструкций следующая работа — приёмка прямого запуска P1 и сценариев P2–P5 на поддерживаемых хостах и характерных задачах. Для P6 нужны конкретный выбранный сервис и проверяемая операция; P7 требует отдельной приёмки интерфейса и опубликованного пакета. Точное состояние, зависимости и критерии — в [плане](lifecycle.ru.md), выполненные проверки — в [журнале](validation.ru.md).

## Технические критерии готовности существующих маршрутов

1. Проверить результаты готовых GUI-пакетов точной версии и первого запуска на Windows и обеих
   архитектурах Mac. Встроенный движок не требует установки Python пользователем;
   самостоятельный PowerShell сохраняет более узкий набор операций.
2. Проверить характерный реальный месяц и поддерживаемые форму/год через выбранный
   расчётный инструмент и ручной ELSTER; сохранить реальные доказательства приватно.
3. Проверить первый запуск подключённого GUI, восстановление после ошибок и
   продолжение сессий с нетехническими пользователями Windows/macOS.
4. Добавлять напоминания через определённый разрешённый планировщик с проверкой
   доставки; сохранённая дата ещё не является напоминанием.

[Windows](windows.ru.md), [восстановление](../skills/de-business-kit/references/recovery.md)

## Ответственность документации

Код, схемы команд и тесты определяют, что реализовано. Эта страница описывает
текущий объём; архитектура и онтология объясняют устройство; переносимые инструкции
направляют установленного ассистента; пользовательские руководства объясняют
задачи. Датированные исследования фиксируют проверку источников, журнал валидации —
реальные запуски. Обновление описания кода не обновляет правовое исследование и не
подтверждает GitHub CI. Сохраняйте это разделение; см. [AGENTS.md](../AGENTS.md)
и [правила участия](../CONTRIBUTING.ru.md).

Выпуски: единая версия, воспроизводимые пакеты и проверка происхождения описаны в [Версии, подписи и проверка выпусков](releases.ru.md).
