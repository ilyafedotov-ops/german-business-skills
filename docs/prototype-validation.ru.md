# Проверка прототипа рабочего пространства

[English](prototype-validation.md) | [Русский](prototype-validation.ru.md)

Текущие возможности описаны в [состоянии проекта](project-status.ru.md). Датированные записи ниже сохраняют исходный объём и результаты; они не доказывают работоспособность последующих изменений.

Проверено **2026-10-25** на macOS ARM64, Node 22.23.2 и Playwright 1.63.0. Область проверки — статический прототип с вымышленными данными в `prototype/`, не установленный навык, производственное приложение или реальные бухгалтерские сервисы.

## Проверки браузера

- Команды: `npm run test:browser` и `npm run test:browser -- --browser=webkit`.
- Chromium и WebKit открывают настоящий `prototype/index.html` через `file://`, без сервера разработки и сетевых запросов приложения.
- Пройдены четыре сценария: выбор и добавление примеров из папки; исправление суммы счёта с невыясненной категорией; исследование, откладывание и связывание платежа; закрытие, повторное открытие и продолжение работы.
- Дополнительно проверены пустой каталог и поиск, отсутствие выбранных файлов, неверные поля с переходом к источнику ошибки, помощь, отмена и подтверждение сброса, отказ хранения, конфликт двух вкладок. Этап просмотра папки и выбранные файлы сохраняются при перезагрузке.
- Проверены все пять основных экранов, проверка счёта, исследование платежа, настройки и вводная последовательность. Размеры окна: 1440×1000, 390×844 и 320×844. Узкие экраны проверены на горизонтальное переполнение страницы.
- Клавиатура: переход к содержимому сохраняет текущий экран и фокусирует main; ссылки ошибок фокусируют поля; Escape закрывает помощь и возвращает фокус кнопке.
- Неожиданных ошибок консоли приложения и неудачных запросов нет. WebKit выдаёт пять отказов CSP при внедрении служебного стиля снимков Playwright. Отдельная минимальная проверка загрузки и снимка подтвердила происхождение сообщения. Тест отделяет только это точное сообщение во время снимка; CSP приложения не ослаблена, другие ошибки не скрываются.

Зависимости разработки зафиксированы в `package-lock.json`. CI настроен для Chromium в Windows и WebKit в macOS; локальный запуск macOS не доказывает прохождение удалённых заданий.

## Визуальная проверка и Impeccable

Источник требований — описание пяти экранов пользователем и [сохранённая рекомендация](research/gui-ux-recommendation.md). Утверждённого снимка или макета Figma нет. Проверка сопоставляет интерфейс с письменными требованиями, а не заявляет пиксельное совпадение.

Уточнение дизайна использует режим Operate и подход polish из Impeccable: сохранение поведения, ясное следующее действие, единые элементы управления, видимые подсказки, читаемый вспомогательный текст, структурная адаптация. Убраны декоративные надзаголовки и иллюстрация. Навигация использует SVG-значки и переносится на узком экране. Внешние шрифты и изображения не нужны.

Снимки Home и проверки счёта на широком экране, проверки счёта при 390/320 px и ошибки хранения находятся в исключённой из Git папке `output/prototype/`. Примеры имён: `chromium-home-desktop.png`, `chromium-review-desktop.png`, `chromium-review-390.png`, `chromium-review-320.png`; есть соответствующие снимки WebKit. Все данные вымышленные. Пиксельной разницы с эталоном нет, поскольку эталон текстовый.

По замечаниям дизайна увеличен мелкий текст, затемнены второстепенные надписи, исправлен контраст кнопки сброса при наведении. Детектор Impeccable также отметил предпочтение Inter: оно удалено в пользу системного шрифта. Исключений детектора не добавлено. Это не сертификация WCAG.

## Автоматические проверки

`npm test`: пять тестов состояния прошли — точный разбор суммы, сохранение черновика, отказ записи, конфликт вкладок, повреждённые данные. Первый запуск не прошёл из-за отсутствия модуля; после реализации прошёл. Регрессионные проверки воспроизвели потерю этапа ввода и неверную клавиатурную навигацию до исправления. WebKit выявил необходимость явно возвращать фокус.

`GBK_TEST_DOCKER_IMAGE=mcr.microsoft.com/dotnet/sdk:9.0 python3 -B -m unittest discover -s tests -v`: **173 теста прошли**, включая границы проверки пакета и взаимодействие с PowerShell через контейнер разработчика. Это не проверка Windows PowerShell 5.1 на Windows.

## Что ещё не проверено

Не проводились модерируемое исследование удобства, исследование со скринридером, сеанс Windows на реальном устройстве, импорт настоящей папки, просмотр PDF, OCR, работа с живыми соединениями, бухгалтерские записи, расчёт налогов или отправка деклараций. Английский интерфейс требует локализации перед двуязычным выпуском. До выбора производственной оболочки и подключения проверенных команд нужны испытания с нетехническими пользователями Windows/macOS.
