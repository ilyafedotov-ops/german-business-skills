# История изменений

[English](CHANGELOG.md) | [Русский](CHANGELOG.ru.md)

Версии следуют Semantic Versioning. Все выпуски ниже — предварительные: это не
сертификация бухгалтерской корректности или совместимости настольных приложений.
Исторические этапы впервые публикуются 2026-10-26 с сохранением исходных коммитов.

## Не выпущено

## 0.11.0-preview.1

- Добавлены защищённые записи выставления/исправления/доставки счетов, неизменяемые подтверждения и продолжение точной попытки; действия провайдера, отправка и получение адресатом разделены.
- Добавлен opt-in API-адаптер черновиков/чтения Lexware Office с проверкой стоимости/доступа, сохранением намерения создать документ, без автоматического повтора неопределённого исхода и с браузерным продолжением того же объекта. Браузерный Office L принят пользователем E2E для нулевых тестовых документов; живая приёмка API и более широких ненулевых сценариев остаётся открытой.
- Добавлены сохранённые сверки счёта и поступлений: исключение учтённой предоплаты, частичные оплаты/возвраты, блокировки корректировок/валюты/охвата и проверка актуальности. Подготавливаются DE/EN/RU клиентские запросы и отдельные EN/RU закрытые проверки; автоматической отправки или отнесения платежей у провайдера нет.
- Продолжение подачи связано с источниками подготовки периода; прежние версии сохраняются. Добавлены сценарии запроса изменения авансов Einkommensteuer, закупок товаров в ЕС и клиентских оплат на основе источников; регламентированного расчёта или транспорта ELSTER нет.
- Ограниченный UBL/CII-инспектор сохраняет указанные в счёте предоплату и округление; итоги документа отделены от текущих расчётов.
- Добавлены общие проверки стоимости до платной настройки и приватности скриншотов до публикации. Решение не повышать тариф сохраняется; реальные данные аккаунта остаются вне публичных материалов.
- Добавлены инструменты исследования/оценки по источникам и EN/RU руководства. Приёмка релиза/платформ требует проверок точного тега и проверенных файлов.
- Исправлена проверка цепочки вложенных корректировок: неопределённая доставка оригинала, конкурирующая корректировка и повреждённые подтверждения предков блокируют новую попытку; наблюдаемый результат уже начатой попытки по-прежнему можно записать.

Нет автоматической миграции личной папки, полного регламентированного регистра, подписи desktop-приложений или живой передачи ELSTER. API-адаптер требует существующего поддерживаемого доступа; браузерная работа не требует повышения тарифа.

## 0.10.0-preview.1

- Основной путь — ассистент и личная папка бизнеса; добавлены вызовы скиллов, запросы установки, примеры жизненного цикла и наглядные руководства EN/RU. GUI остаётся необязательным.
- Общие предпосылки, повторное использование подтверждённых фактов, актуальные первичные источники и отдельная проверка арифметики применяются во всех сценариях; описаны обработка данных AI-провайдерами, выбор моделей и помощь браузера/компьютера по задаче.
- Удалён архив истории документации; актуальные сводки состояния и проверок сохранены, прежние материалы доступны в Git.

- Репозиторий стал маркетплейсом плагинов Claude: `.claude-plugin/marketplace.json` устанавливает опубликованный выпуск, закреплённый по тегу и коммиту, поэтому пользователи Cowork, чата и Claude Code добавляют `ilyafedotov-ops/german-business-skills` в **Customize → Plugins** за три шага. README и руководство по установке EN/RU переписаны вокруг этого пути, Codex оставлен как сокращённый путь со скиллами в проекте, схемы установки перерисованы, добавлен шаг выпуска для переноса закрепления.
- Добавлены распределение платежей по счетам между периодами, читаемые остатки EN/RU и подробности GUI EN/RU/DE; сохраняются частичная оплата, переплаты, возвраты и исправления, выявляются разные валюты/неясное направление, устаревшая основа сверки блокирует отчёт-источник подачи.
- Добавлены native-диагностика/снятие блокировок и общие метаданные писателей; Python и PowerShell сохраняют точные исходные байты блокировки в истории. Общий native-модуль явно включён в пакет.
- GUI использует результат проверки подачи повторно внутри одного заблокированного снимка; добавлен синтетический профилировщик. Язык нового пространства по умолчанию — английский; явные и сохранённые предпочтения не меняются.
- Добавлен необязательный POSIX runner Codex для десяти синтетических сценариев в новых сессиях, независимых проверок состояния/действий и отдельной оценки по критериям. Это инструмент разработчика, не требование к пользователю и не автоматическая юридическая или качественная сертификация.

- **Несовместимо для входных данных денежных записей:** новые локальные денежные записи используют `schema_version` 2. Каждая строка фиксирует НДС так, как он указан в доказательстве (`stated`, `none_stated` или `unresolved`), и может ссылаться на действующее одобренное предложение, которое она оплачивает. Модуль проверяет, что нетто плюс НДС равно сумме строки, отклоняет неодобренные, заменённые предложения и предложения другой деятельности и сохраняет отпечаток каждой ссылки. Записи без НДС строк больше нельзя внести; начинайте с `accounting-template --kind entry`.
- Отчёты периода (схема 2) группируют указанный НДС по валюте, виду движения и ставке, отмечают `vat_unresolved` и `vat_not_recorded` и добавляют раздел НДС в Markdown EN/RU. Отчёты и проверка подачи останавливаются, если связанное предложение изменилось. Форма записи в GUI получила поля НДС и выбор одобренного счёта на EN/RU/DE.
- Записывающие утилиты ждут до пяти секунд завершения другой участвующей утилиты, а не останавливаются сразу. Блокировка хранит процесс, компьютер и время; `doctor` относит оставшуюся блокировку к активной, устаревшей или непроверяемой, а новые `workspace.py unlock` и проверка блокировки в GUI снимают только блокировку завершившегося процесса (или непроверяемую — после явного подтверждения) и сохраняют её в истории и аудите. Блокировки native `windows.ps1` тоже хранят компьютер.
- Отказ из-за ссылочной папки теперь называет звено пути со ссылкой и его реальное расположение — в Python и native PowerShell. В macOS и Linux атомарная и исключительная запись синхронизирует и папку, чтобы сбой не потерял завершённое переименование.

Реестр учёта остаётся схемы 1; существующие записи остаются читаемыми, попадают в отчёты и сторнируются без миграции. Суммы указанного НДС — исходные данные для программы расчёта, а не декларация по НДС.
