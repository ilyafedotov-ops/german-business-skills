# Добровольные проверки навыков в новых сеансах

[English](README.md) · [Русский](README.ru.md)

`scenarios.json` содержит поведенческие запросы и критерии проверки. Программа на стандартной библиотеке Python выполняет десять ограниченных критических сценариев через явно установленный **Codex CLI**. Для других хостов и учебного портала с браузером нужны отдельные испытания. Это инструмент разработчика, не часть установленного навыка и не недетерминированный барьер CI. Вызов модели может быть платным; просмотр списка и модульные тесты модель не вызывают.

```sh
python3 -B tools/run_evals.py --list
python3 -B tools/run_evals.py --case archive-integrity --output /absolute/new/eval-evidence
python3 -B tools/run_evals.py --all --output /absolute/new/ten-case-evidence --timeout 150
```

`--codex /absolute/path/to/codex` выбирает исполняемый файл; `--model HOST_MODEL` — поддерживаемую хостом модель. Программа не закрепляет модель. Без `--model` действует модель чистой конфигурации хоста, которая может отличаться от настроенной пользователем. Адаптер использует параметры, проверенные в Codex CLI 0.164.0; неподдерживаемая версия завершается ошибкой без обхода ограничений. Существующая аутентификация Codex используется с `--ignore-user-config`: обычные подключения к аккаунтам, профили и настроенные hooks не запрашиваются. Программа не копирует учётные данные, не загружает реальные документы, не включает веб-поиск, не устанавливает плагины, не меняет настройки провайдера и не добавляет адаптеры внешних сервисов. Используйте предназначенный маршрут аутентификации Codex/OpenAI; для другого провайдера нужен отдельно проверенный адаптер, а не скрытое копирование настроек хоста.

Для каждого сценария запускается новый ephemeral-сеанс CLI с отдельной рабочей директорией, полной копией навыков, синтетическими фактами и штатными средствами записи рабочей папки. Снимок исходников фиксируется один раз на запуск; в него входит только `skills/`, без репозитория, тестов, сценариев и критериев. Результаты записываются в новую абсолютную директорию вне репозитория; существующая директория и символьные ссылки в пути запрещены. Сеанс ограничен временем: по умолчанию 300 секунд, максимум 3600. При превышении сохраняются частичный журнал и неуспешный результат. Программа запуска хоста сейчас поддерживает только POSIX и завершает группу процессов после успеха, ошибки или тайм-аута до проверки файлов. Чтение и хеширование используют закреплённые дескрипторы директорий и отклоняют символьные ссылки и специальные файлы; побочная запись Python bytecode отключена в окружении дочернего процесса. Запуск в Windows явно отклоняется до отдельной реализации и проверки завершения дерева процессов; поддержка Windows самим продуктом не меняется.

Десять сценариев проверяют начало без настройки, сохранение внешней системы учёта, внедрение инструкций в счёт, оригиналы, запрет удаления при проверке, разовую и постоянную смену языка/режима, отсутствие подтверждения отправки, неопределённый результат отправки и границы проверки XML. В фикстурах нет реального подключения и квитанции об отправке. Внешняя система и факты профиля записываются штатными командами; PDF/XML — синтетические заглушки, не фикстуры технической валидации счетов. В этих сценариях должны сохраниться все исходные файлы, факты профиля и регистр/выбор системы учёта; при постоянной смене предпочтений нужны новые значения и реальная история настройки. Для допустимого действия за пределами этой узкой фикстуры нужен отдельный сценарий, а не ослабление проверки.

Результаты разделяют два вида доказательств:

- **Детерминированные проверки** читают фактические хеши файлов, предпочтения, штатный регистр, историю, снимок навыков, завершённый поток событий и текст наблюдавшихся команд. Тесты подтверждают обнаружение повреждения оригинала, пропущенной смены предпочтений, наблюдавшейся сетевой команды и тайм-аута, даже если агент заявляет об успехе. Анализ текста команд ограничен и не заменяет полный мониторинг сети и инструментов.
- **Оценка диалога** хранится вне копии сеанса в `rubric/`. Каждый критерий получает `pending_review`. Проверяющий изучает журнал, реальные файлы и состояние и записывает pass/fail/uncertain со ссылками на доказательства. Заявление агента и успешные проверки файлов не закрывают критерии. Программа не превращает вручную изменённые листы оценки в общую сертификацию.

Код `0` означает успех выбранных детерминированных проверок при общем статусе **pending_review**. Код `1` означает провал хотя бы одной проверки выполненного/попытанного сценария. Код `2` означает ошибку конфигурации, подготовки или запуска хоста; сохраните материалы и отчёт `incomplete`, не считайте отсутствующие сценарии успешными.

Директория доказательств содержит версии пакета/программы/хоста/Python/платформы, хеши исходников/сценариев/программы, запрошенную модель, точную команду, даты, длительность, журналы, stderr, хеши состояния до/после, копии навыков, созданные файлы и отдельные листы оценки. `requested_model: null` не определяет фактическую модель. Утверждение о модели должно опираться на данные хоста. Не помещайте сюда реальные сведения и по умолчанию не добавляйте локальные журналы хоста в Git.

Разные директории и sandbox `workspace-write` **не обеспечивают конфиденциальность чтения**. Критерии не включаются в запрос и копию навыков, а запрос ограничивает работу своим сеансом; однако хост с широким доступом потенциально может прочитать соседние доказательства или исходный репозиторий. Глобальные инструкции и правила хранения данных провайдером также влияют на испытание; ephemeral-сеанс не доказывает отсутствие хранения у провайдера. Для противодействия намеренному поиску скрытых критериев нужна отдельно настроенная среда ОС/контейнера, куда подключены только снимок навыков и фикстура, а критерии и доказательства остаются у наблюдателя. Эта программа не подтверждает такую изоляцию, юридическую/налоговую правильность, живую интеграцию, браузерную работу или совместимость с Windows.

Регрессионные проверки программы:

```sh
python3 -B -m unittest discover -s tests -p test_eval_runner.py -v
python3 -B tools/check_package.py
git diff --check
```
