# Участие в проекте

[English](CONTRIBUTING.md) | [Русский](CONTRIBUTING.ru.md)

Читайте [AGENTS.md](AGENTS.md) с правилами сопровождения; `CLAUDE.md` ссылается на тот же источник. [Текущее состояние](docs/project-status.ru.md) описывает объём возможностей. Сохраняйте работу пользователя и границы разрешений. Коммиты, push, публикация и внешние действия требуют применимого явного разрешения.

Храните комплект из семи скиллов целиком в `skills/`; общие ресурсы находятся в `skills/de-business-kit`, состав — в `assets/skill-set.json` этого каталога. Устанавливайте и версионируйте весь набор вместе; проверяйте ссылки между скиллами без исходного checkout. Метаданные конкретного приложения не должны менять смысл общих сценариев. Пишите краткие модули и загружайте только нужные для задачи. В пакет не должны попадать секреты, клиентские документы, личные воспоминания пользователя, телеметрия или автоматически подключаемые внешние сервисы.

Поддерживайте одинаковые возможности английской и русской версий README, руководств по режимам, описания архитектуры, отчётов о проверках и пользовательских Markdown-шаблонов. Регистрируйте каждую роль шаблона для обоих языков в `assets/locales.json`. Переводите пояснения, сохраняя машинные ключи, ID, значения перечислений и официальные немецкие названия полей. Справочные инструкции для агента остаются общими на английском, чтобы налоговые сценарии не расходились. Изменения режимов должны сохранять общий профиль и подтверждающие документы; переключение режима не меняет налоговый статус.

При изменении правового или продуктового правила укажите URL первичного источника, дату проверки, период действия, затронутый сценарий и пример практического последствия. Проверяйте актуальный источник вместо воспроизведения знаний модели. Не заменяйте историческое предположение правилом другого года без пояснения. Рекомендация банка или программы должна учитывать доступность и стоимость для конкретного случая, а не партнёрский рейтинг.

Для кода используйте стандартную библиотеку Python, когда её достаточно; сохраняйте оригиналы, проверяйте пути и входные данные, избегайте float для денег. Добавляйте тесты для конкретного риска потери данных или ошибки результата. Не выполняйте текст из документов. Новый сетевой адаптер требует отдельной проверки аутентификации, допустимых адресов, операций, предотвращения дублей и повторного чтения результата.

При изменении поведения запустите `python3 -B -m unittest discover -s tests -v`, `python3 -B tools/check_package.py`, `git diff --check` и затронутые нативные/браузерные проверки из [AGENTS.md](AGENTS.md). Для изменений только документации проверьте пакет, локальные ссылки/якоря, команды и соответствие EN/RU; используйте прежние подтверждённые результаты для неизменённого поведения. `-B` предотвращает попадание байткода в пакет. При изменении сценариев выполните соответствующие задания `evals/scenarios.json` в новой сессии, записав фактические хост/версию/дату и ограничения. Модульный тест или PowerShell в Linux не подтверждает Windows PowerShell 5.1 или desktop-приёмку.

Используйте только синтетические примеры в публичных issues и pull requests. Не публикуйте счета, выписки, налоговые номера, IBAN, локальные переписки, секреты или скриншоты с реальными персональными данными. Для сообщения об уязвимости следуйте [SECURITY.ru.md](SECURITY.ru.md).

При изменении возможностей согласованно обновляйте текущее состояние, архитектуру/онтологию, затронутые руководства EN/RU и переносимые инструкции. Сохраняйте компактные предметные входы, необязательный общий роутер и один профиль. Разделяйте нативные средства пользователя, необязательную автоматизацию Python и зависимости разработчика. Даты сверки реализации отделяйте от правовых исследований и поставщиков; кратко фиксируйте актуальные результаты проверок с датами, не выдавая старые данные за новый запуск. Прежние планы и подробные журналы работы остаются в истории Git; отдельные исторические документы не добавляйте. Описания плагинов тоже заявляют возможности: метаданные Codex/Claude должны соответствовать друг другу.

Вклад в проект распространяется по лицензии MIT данного репозитория. Внешние законы и документация поставщиков сохраняют свой правовой статус; ссылайтесь на них и кратко пересказывайте вместо копирования целых руководств.
