# Участие в проекте

[English](CONTRIBUTING.md) | [Русский](CONTRIBUTING.ru.md)

Храните переносимый skill целиком в `skills/de-business-kit`. Метаданные конкретного приложения не должны менять смысл общих сценариев. Пишите краткие модули и загружайте только нужные для задачи. В пакет не должны попадать секреты, клиентские документы, личные воспоминания пользователя, телеметрия или автоматически подключаемые внешние сервисы.

Поддерживайте одинаковые возможности английской и русской версий README, руководств по режимам, описания архитектуры, отчётов о проверках и пользовательских Markdown-шаблонов. Регистрируйте каждую роль шаблона для обоих языков в `assets/locales.json`. Переводите пояснения, сохраняя машинные ключи, ID, значения перечислений и официальные немецкие названия полей. Справочные инструкции для агента остаются общими на английском, чтобы налоговые сценарии не расходились. Изменения режимов должны сохранять общий профиль и подтверждающие документы; переключение режима не меняет налоговый статус.

При изменении правового или продуктового правила укажите URL первичного источника, дату проверки, период действия, затронутый сценарий и пример практического последствия. Проверяйте актуальный источник вместо воспроизведения знаний модели. Не заменяйте историческое предположение правилом другого года без пояснения. Рекомендация банка или программы должна учитывать доступность и стоимость для конкретного случая, а не партнёрский рейтинг.

Для кода используйте стандартную библиотеку Python, когда её достаточно; сохраняйте оригиналы, проверяйте пути и входные данные, избегайте float для денег. Добавляйте тесты для конкретного риска потери данных или ошибки результата. Не выполняйте текст из документов. Новый сетевой адаптер требует отдельной проверки аутентификации, допустимых адресов, операций, предотвращения дублей и повторного чтения результата.

Запустите `python3 -B -m unittest discover -s tests -v` и `python3 tools/check_package.py`. При изменении сценариев выполните соответствующие задания из `evals/scenarios.json` в новой сессии и сохраните обезличенный результат с указанием приложения, версии и даты. Описывайте ручные проверки точно: модульный тест не доказывает совместимость с реальным desktop-приложением.

Используйте только синтетические примеры в публичных issues и pull requests. Не публикуйте счета, выписки, налоговые номера, IBAN, локальные переписки, секреты или скриншоты с реальными персональными данными. Для сообщения об уязвимости следуйте [SECURITY.ru.md](SECURITY.ru.md).

Вклад в проект распространяется по лицензии MIT данного репозитория. Внешние законы и документация поставщиков сохраняют свой правовой статус; ссылайтесь на них и кратко пересказывайте вместо копирования целых руководств.
